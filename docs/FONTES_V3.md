# Pesquisa de fontes meteorológicas gratuitas — v3 (05/11/2026)

Método: documentação oficial localizada por busca na web (a sessão de auditoria não alcança sites externos diretamente), respostas brutas já arquivadas pelo projeto na branch `weather-archive` e a documentação anterior do repositório. A coluna **Verificação** diz de onde veio cada informação; itens marcados "a confirmar" precisam de uma leitura direta da documentação antes de qualquer integração.

Critérios resumidos por fonte: instituição, produto/variáveis, cobertura e resolução, atualização e latência, histórico, acesso (API, autenticação, limites), licença e redistribuição, uso em GitHub Actions, disponibilidade em Naviraí/Diamantino, vantagens, limitações, custo real, dificuldade e benefício. Prioridade: **P1** integrar já, **P2** próxima fase, **P3** opcional/experimental, **P4** só com autorização ou cadastro.

## 4. Recomendações de prioridade

1. **Já feito nesta entrega**: metadados de rodada Open-Meteo, passo nativo por modelo, estações INMET corretas com token opcional, variáveis complementares do determinístico.
2. **Próximo passo de maior valor científico**: obter o token do INMET (e-mail ao cadastro do INMET ou Central de Serviços) para A949/A752, e confirmar a identidade da exportação Embrapa. Sem observação, nenhuma calibração é possível.
3. **Fase 4 (mapas)**: GIBS GOES-East (GeoColor/Band 13, 10 min) + IMERG por GIBS + manter RainViewer para radar; DSAT/INPE apenas se o padrão de tiles for confirmado e a carga autorizada.
4. **Processamento local (não no Actions)**: ECMWF Open Data (membros originais, rodada identificada), MERGE e CHIRPS v3 para referência em grade; publicar apenas derivados compactos.
5. **Não fazer**: scraping de portais autenticados, uso de APIs com período de teste pago, reutilização de chaves expostas, WeatherNext 2 direto no Google Cloud sem confirmar custo zero.
